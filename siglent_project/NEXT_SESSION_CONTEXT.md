## What we were trying to build

Two new long-term analysis pipelines to replace `stubbs_longterm_shared_v2.py`:

### Pipeline A: Uniform slicing (`stubbs_longterm_uniform.py`)
Same as shared_v2 but replace `adaptive_slice_periods` with `slice_periods` (fixed-interval uniform cutting from first detected period boundary). Clock drift is handled entirely by EMA inside `analyze()` — no per-period peak detection needed. The recording is continuous back-to-back periods so uniform slicing with `period_n = round(fs / rep_rate)` is exact.

### Pipeline B: xcorr stitching (`stubbs_longterm_xcorr.py`) ← THE IMPORTANT ONE
**Core idea (Cyrus's):** Process each 30s chunk using the EXACT same `chirp_stubbs_analysis.analyze()` call we use for the chirp/alpha sweep recordings. This gives per-chunk smoothness identical to the 30s sweep recordings. Then stitch chunks together using template cross-correlation to get absolute Δτ reference.

**Stitching formula:**
```
offset_i = xcorr_lag(T_return_i, T_return_1) − xcorr_lag(T_launch_i, T_launch_1)
Δτ_absolute_i = Δτ_local_i + offset_i
```
Where `T_launch_1`, `T_return_1` are from chunk 1 (the T_0 reference), and `xcorr_lag` uses `xcorr_lag_shape_fit` from `chirp_stubbs_analysis.py`. Stitching precision ≈ δ_period/√N_template ≈ sub-ns.

## Why period-to-period smoothness differs between 30s sweep and 35min longterm

The 35min shared-template recordings show high-frequency period-to-period jumps (large σ) while 30s sweep recordings are smooth. The root cause is **template mismatch**: the shared template is built at T_0, but by t=12 min the temperature has drifted and the burst shapes changed slightly. The CCF between a current period and the T_0 template is noisier than between a current period and a same-epoch template. In the 30s sweep, template and evaluation periods are always within 30s of each other → near-perfect match → smooth.

The PNG saves to `<wav_dir>/../stubbs_pipeline_v1/` relative to the wav file — so the chunk wav MUST be in its own subdirectory to get correct PNG placement.

**Return dict keys from analyze():**
- `r['T_launch']`, `r['T_return']` — templates
- `r['tau_launch_sf']`, `r['tau_return_sf']` — per-period TOF (μs)
- `r['sigma_launch_sf']`, `r['sigma_return_sf']` — per-period LS uncertainty (μs)
- `r['sigma_dt_sf']` — combined δ(Δτ) = √(δ_L² + δ_R²) (μs)
- `r['delta_tau_sf']` — per-period Δτ = τ_return − τ_launch (μs)
- `r['n_eval']` — number of evaluation periods

## Key instrument facts

- **PicoScope**: TIMEBASE=64 → 1.024590 MHz, Ch A ±2V (use `--adc-range 5V` or `10V` for flat3db)
- **SDG**: 10.11.13.230:5025, SDG_SR=400kHz, max 20Vpp direct drive
- **SPA1010**: ×10 gain, ±6.5V input max (13Vpp), ±13V output max (26Vpp) — PROBLEMATIC: protection triggers ~14-15V output; needs very careful startup procedure (power on with NO load connected, then connect piezo)
- **SR560**: ×100 gain, AC coupled
- **ECM999**: condenser mic, phantom box required
- **Piezo array**: ~90nF capacitive load, f₀=41.3kHz, Q=22.8, τ_ringdown≈172μs
- **BSWV H(f)**: `ecm999_stepped_sine_bswv_20260716_013405.npz` — USE THIS, not burst8ms files
- **Correct chain**: SDG → [SPA1010 ×10 if needed] → piezo → air → reflector → air → ECM999 → phantom box → SR560 → PicoScope Ch A

## Sign convention

**BATPING sign**: warming → Δτ DECREASES (sound faster → shorter TOF)
- Δτ negative relative to baseline = **warming**
- Δτ positive relative to baseline = **cooling**
- Sensitivity: 10.3 μs/°C (2m round trip at 20°C)
- Plot y-axis: `'Δτ = τ_return − τ_launch (μs)'`
